# Методы классификации — теория

## 1. Наивный Байес (Naive Bayes)

**Идея.** Применяем теорему Байеса для оценки вероятности класса при заданных признаках:

$$P(C \mid x_1, ..., x_n) = \frac{P(C) \cdot P(x_1, ..., x_n \mid C)}{P(x_1, ..., x_n)}$$

«Наивное» допущение — признаки **условно независимы** при заданном классе:

$$P(x_1, ..., x_n \mid C) = \prod_{i=1}^{n} P(x_i \mid C)$$

Это абсолютно неверно в реальности (в SMS слова коррелируют), но работает на практике на удивление хорошо.

**Обучение.** Просто подсчёт частот:
- $P(C)$ — доля документов класса $C$ в обучении
- $P(x_i \mid C)$ — частота слова $x_i$ в документах класса $C$ (с лапласовским сглаживанием, чтобы не было нулей)

Никакой оптимизации, никакого градиентного спуска — один проход по данным.

**Предсказание.** Считаем $P(C) \prod P(x_i \mid C)$ для каждого класса, выбираем максимум. На практике — в логарифмах, чтобы не было underflow.

**Варианты:**
- **MultinomialNB** — для счётчиков слов (наш случай со SMS)
- **GaussianNB** — для непрерывных признаков (предполагает нормальное распределение)
- **BernoulliNB** — для бинарных признаков

**Плюсы:** молниеносная скорость, мало данных нужно, отлично работает на тексте, веса легко интерпретировать (топ-слов класса).

**Минусы:** независимость признаков ломается → плохие *калиброванные* вероятности (часто близки к 0 или 1); страдает на сильно коррелированных непрерывных признаках.

## 2. K ближайших соседей (kNN)

**Идея.** Никакой модели нет вообще. Чтобы классифицировать новый объект — находим k ближайших к нему точек обучающей выборки и берём большинство голосов.

$$\hat{y}(x) = \text{mode}\{y_i : x_i \in \text{kNN}(x)\}$$

Это **lazy learning** / **instance-based**: «обучение» = просто запоминание всех точек.

**Обучение.** Сохраняем `(X_train, y_train)`. Всё.

**Предсказание.**
1. Для нового $x$ считаем расстояние до каждой точки обучения (обычно евклидово: $d(x, x_i) = \sqrt{\sum_j (x_j - x_{i,j})^2}$)
2. Сортируем, берём k ближайших
3. Голосуем (для классификации) или усредняем (для регрессии)

**Почему обязательно масштабирование.** Расстояние складывает квадраты разностей по всем признакам. Если `Glucose` измеряется в десятках, а `DiabetesPedigreeFunction` в десятых долях — Glucose будет доминировать в расстоянии и затирать всё остальное. `StandardScaler` приводит каждый признак к нулевому среднему и единичной дисперсии — теперь все вносят равный вклад.

**Выбор k — компромисс bias/variance:**
- $k=1$ — переобучение, граница «дёрганая», шумит
- $k$ большое — недообучение, граница сглаживается, теряется детальность
- Подбираем по кросс-валидации (как в ноутбуке: цикл по k=1..30, выбрали k=19)

**Плюсы:** простой, без предположений о распределении, естественно работает с многоклассовыми задачами, хорошо ловит локальные паттерны.

**Минусы:** медленный на больших данных (предсказание O(n)), страдает от **проклятия размерности** (в высоких размерностях все точки становятся одинаково «далеко»), требует масштабирования, не любит лишних/шумных признаков.

## 3. Метод опорных векторов (SVM)

**Идея.** Найти **гиперплоскость**, которая разделяет классы с **максимальным зазором** (margin). Из всех возможных разделяющих плоскостей выбираем ту, у которой зазор до ближайших точек обоих классов наибольший — это даёт лучшую обобщающую способность.

**Линейный случай.** Гиперплоскость: $w^T x + b = 0$. Условие правильной классификации с зазором ≥ 1:

$$y_i (w^T x_i + b) \geq 1$$

Зазор равен $\frac{2}{\|w\|}$, максимизируем его — то есть минимизируем $\|w\|^2$:

$$\min_{w, b} \frac{1}{2}\|w\|^2 \quad \text{при} \quad y_i(w^T x_i + b) \geq 1$$

Это выпуклая задача квадратичного программирования. Для неразделимых данных добавляют slack-переменные $\xi_i$ и параметр $C$ (soft margin):

$$\min \frac{1}{2}\|w\|^2 + C \sum_i \xi_i$$

$C$ большое → мало ошибок на трейне, переобучение; $C$ малое → шире зазор, обобщение лучше.

**Опорные векторы.** В оптимальном решении большинство точек лежат «вне» зазора и не влияют на решение. Только те точки, что лежат **на границе зазора или внутри него**, формируют гиперплоскость — это и есть support vectors. Поэтому SVM компактна: модель определяется маленькой долей данных (в нашем случае 107 из ~455).

**Ядерный трюк (kernel trick).** Если данные линейно неразделимы, переводим их в пространство большей размерности через отображение $\phi(x)$, где они становятся разделимыми. Но явно $\phi$ не считаем — пользуемся тем, что вся задача формулируется через скалярные произведения $\phi(x_i)^T \phi(x_j)$. Их заменяем на **ядро** $K(x_i, x_j)$, которое вычисляется в исходном пространстве:

- **linear:** $K(x, x') = x^T x'$ — обычная гиперплоскость
- **poly:** $K(x, x') = (x^T x' + r)^d$ — полиномиальная граница
- **rbf:** $K(x, x') = \exp(-\gamma \|x - x'\|^2)$ — гауссовское, локальное; самый универсальный вариант, обычно хорошо работает «из коробки»

В нашем датасете `rbf` дал F1=0.967 против `linear` 0.948 и `poly` 0.844 — данные слегка нелинейные, RBF подобрал кривую границу.

**Плюсы:** очень устойчив в задачах с многими признаками и малым числом объектов (наш случай: 30 признаков, 569 строк), чёткая теоретическая база (max-margin → хорошая обобщающая способность), компактная модель (только опорные векторы).

**Минусы:** медленно обучается на больших данных (O(n²)–O(n³)), `predict_proba` приходится калибровать отдельно (Platt scaling), сложно подбирать гиперпараметры $C$ и $\gamma$, требует масштабирования.

## Сводная интуиция

| Метод | «Где модель?» | Когда выбирать |
|---|---|---|
| **NB** | В таблицах частот $P(x_i \mid C)$ | Текст, baseline, очень мало данных |
| **kNN** | Нигде — это и есть обучающая выборка | Локальные паттерны, мало признаков, хочется простоты |
| **SVM** | Гиперплоскость + опорные векторы | Мало объектов и много признаков, нелинейные границы (с RBF) |
